# Phase 8 kernel concept audit

`compatibility/kernel-concepts.json` audits the stabilization requirement that
no retained kernel concept depend on one extension. The exact reviewed concepts
are compiled extension composition, event observation, process launch,
runtime-tool plans, semantic client sessions, and dispatch guards. Five have at
least two distinct production, clean-room, or bounded experiment consumers.
The semantic client session retains one explicit unresolved item until Coding
executes the public conformance suite through its generated architecture harness.
The independent TUI released public-module matrix is already complete at commit
`95d0bf4622a7dc6b38a30735b280a8e6b47fbd56`: all eight Linux/Windows lanes in
run `31747559805`, ordinary CI `31747560151`, and documentation run
`31747560119` succeeded. It source-builds public modules and does not claim a
prebuilt-executable matrix, so it closes no different binary criterion.

Compaction, Git workflow, MCP, planning, sandbox, and subagent work remain
optional. Their absence creates no kernel dependency; completed experiments
retain explicit deletion paths and do not stabilize their application-owned
APIs. The quality gate rejects a rewritten or hidden unresolved concept, a
single-consumer retained concept, an unsorted identity, or a change to the
reviewed optional boundary.
No optional experiment was promoted merely to satisfy this evidence.
